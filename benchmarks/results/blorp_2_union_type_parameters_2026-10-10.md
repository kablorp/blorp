# Pilot union type parameters

Fixed unions now accept ordered type parameters and atomic type arguments, for example `Result[T, E]` and `Result[Int, Int]`. The four production files changed are `syntax.brp`, `parse.brp`, `check.brp`, and `specialize.brp`. README and EBNF describe the accepted syntax and remaining limits. Root owns the accompanying generics plan.

Written and checked applications carry ordered lists. Declaration owner plus parameter position remains the identity authority. Resolution validates application arity before resolving atomic children. Constructors and patterns substitute each payload through its owning union's complete parameter list. Specialization traverses every child and keys instances by nominal declaration and all ordered arguments, including phantom arguments. Simultaneous replacement remains terminal, preserving caller-owned rigid parameters during forwarding.

Inference still proceeds from arguments in source order, then application children from left to right. Child-expression errors precede constraints; generic conflicts and missing inference precede ordinary mismatches. Successful calls publish only complete substitutions. At the first conflict, the diagnostic expectation substitutes established candidates and retains accepted, uninferred callee-rigid parameters: `Tri[Int, Int, B]` is an honest snapshot when `B` has not been visited. The snapshot validates owner and position and never escapes as an accepted call substitution. Earliest candidate origins survive agreeing constraints.

Written nesting, contextual result inference, union-valued or managed payloads, and multiple fields remain unsupported. Concrete payloads must still be `Int`; a later `String` payload rejects even when only another variant is constructed, preserving the initiating request span and payload declaration note. Bare unary application diagnostics retain their wording. New plural missing-argument and count-mismatch diagnostics carry typed counts; list-parser diagnostics now describe atomic argument lists.
