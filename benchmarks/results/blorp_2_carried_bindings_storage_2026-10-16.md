# Carried-bindings early host allocation and storage screen

Observed on 2026-10-16.

The current host materializes `Define(ValueDefinition)` as an additional managed
wrapper. At every sampled N it adds N allocations/backing mallocs, N live objects
and 40N managed live bytes over ordinary definitions. All 24 scalar-counter rows
were observed, all five allocation callbacks passed, and the separate compile-only
inspection callback passed after normal generated-input setup. This does not
establish eventual pilot layout, isolated instruction cost or the final +3% gates.

## Workload and authority

The disposable allocation TestSuite uses actual current ValueDefinition, ValueId,
TypeRef and Span, plus the reviewed proposed LoweredStep/ValueParameter and full
recursive Join/JoinArm declarations. Real check/specialize/lower setup obtains
N distinct entrypoint definitions before measurement; no opaque ID is forged.
The three cases rebuild identical ordinary integer definitions, add Define
wrappers, or build id/type/span parameters. IDs, types, payloads, spans, lengths
and black-boxed checksums remain observable. Setup and printing are outside the
scalar endpoints; result/seed lengths are read after final endpoints.

The common production ValueOperation still includes legacy JoinValue; its removal
is not modeled. No Join is executed, and no alternative carrier or pilot analogue
was added. Parameter construction omits operations, so its lower count is not an
equal-work speedup. Scalar control requires active memory/oracle/byte gates and
nonallocating scalar counter reads. Per-width post-epoch cleanup and checksum assertions pass.

## Exact C storage and lifetime mechanism

All anchors below refer to the unmodified C hash above; compact symbols are local
to that artifact. `C_EXCERPTS.md` contains verbatim bounded ranges.

- `brp_tyx` (17307–17329) is the ordinary managed ValueDefinition: long ID,
  managed TypeRef pointer, managed ValueOperation pointer, inline Span. Its make
  function calls blorp_alloc; destruction releases type/operation. IntegerValue
  itself has its shared fresh allocation path at 746–753.
- `brp_ty7d` (16008–16051) is a managed LoweredStep with tag, release mask and
  Define/Join pointer payloads. Both fresh constructors call blorp_alloc(sizeof
  brp_ty7d). Define owns its ordinary record; its destructor releases that child,
  and the Join case releases its Join child. Reuse helpers exist, but the measured
  constructor loop invokes the fresh Define constructor, not the reuse helper.
- The Define loop makes the ordinary record then calls brp_c_1Z (118249–118264).
  Pointer-managed lists retain/store that element then release its temporary
  (118265–118288). Plain and parameter lists also hold managed record pointers.
  Capacity checks are real; this is not inline record/union list storage. Field
  copy retains the shared TypeRef; Span is copied inline. No deep-copy claim.
- `brp_ty7c` (26574–26593) is a separately managed ValueParameter carrying long ID,
  TypeRef pointer and inline Span. It has its own allocation and type-child drop.
- Full proposed Join survives: `brp_ty7f` (26647–26675) retains result parameter,
  carried list, scrutinee, owner, arms list and reads list; its destructor releases
  the four managed fields. `brp_ty7e` (26608–26630) retains label, steps list, yielded
  value and carried list. The steps-list field closes the recursive shape. Both
  step variants, their constructors/destructors, and scan branches are present;
  the dormant Join payload was not removed by library DCE.
- Step scans load a pointer element, check its tag, unbox Define and inspect the
  definition; Join remains a distinct invalid-in-this-workload branch
  (118389–118411). Parameter scans load their record fields (118413–118429).
- Step counter reads surround construction and scan (118636–118665). Length and
  checksum observations follow the final endpoints; reporting follows them, then
  the result list is released at 118694–118696. Plain and parameter functions have
  the same order (118574–118634, 118698–118759). Seed lists remain borrowed and
  needed after endpoints. The native scalar reader at 43394–43396 constructs no

  window or library-runtime execution is inferred.

## Limits and recommendation

This screen establishes current-host allocation/storage behavior for these
ordinary-definition and parameter paths. The host's boxed union is **not proof**
of eventual pilot inline/boxed union behavior or self-compile cost; that separate
assessment remains with reviewers. No pilot analogue or alternative carrier was
introduced. Managed edge transfers, actual joins, binding-width snapshot COW,
retired instructions, whole-input costs and source-to-C costs are unmeasured here.

Isolated micro retired instructions are unavailable. Function profiling reports
time/calls; timing the whole test command includes compiler/setup/harness work.
Neither is a substitute. The final hard **+3% allocations and minimum retired
instructions per unchanged source-to-C/shared input** remains outstanding, with
reviewed capability/cumulative baselines. No intentional UTF-8 change waives old
caps. Production hard 800 added/+250 net and tests 1,400 added/+450 net stay in
force; feature budgets remain unapproved.

Recommendation: accept the screen as limited observed evidence, explicitly price
the host wrapper and parameter storage, and retain the pilot/whole-cost question
for root/two-reviewer assessment. Do not claim broad-migration readiness. No
production edits, alternative representation, extra fixture or commit is included.
