# Blorp 2 String interpolation

Quoted and LF-joined pipe Strings accept `${expression}` holes. Holes require
String values, evaluate once in written order and retain normal scope, generic
inference and purity checks. Primitive conversions remain explicit. Raw blocks
retain literal `${` text. Nested interpolation, interpolation in patterns,
builtin labels and closed constant initializers are rejected.

The parser publishes a flat transient expression list and coalesces consecutive
decoded text once, retaining physical source spans for errors. A body-local
pending node survives ordinary inference and disappears during checking. Checked
output uses only existing runtime String concatenations, balanced to logarithmic
depth. Association and allocation timing differ from a handwritten left fold;
leaf evaluation order does not. Compiler source still uses existing syntax so
the currently pinned seed can build the feature.

Existing multiline syntax already covered the useful static compiler literals;
the audit found no worthwhile all-static LF concat conversion. No cosmetic
compact-C or raw-literal churn was made.
