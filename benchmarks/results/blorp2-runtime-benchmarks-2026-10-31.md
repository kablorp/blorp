# Blorp 2 runtime benchmarks against the legacy compiler, 2026-10-31

This report compares programs generated by Blorp 2 (`blorp_2/build/compiler`)
with programs generated by the legacy compiler (`bin/blorp`). Each runs the
same benchmark, with the same native flags, through
[`bench.sh`](../bench.sh). It also records which legacy benchmark sources
Blorp 2 can compile today.

## Summary

- **Blorp 2 compiles none of the 29 legacy sources in `benchmarks/blorp/`.** All
  fail at lexing or parsing. In 23 sources the first error is an infix
  arithmetic operator (`-`, `%`, `*`, `/`), which is milestone 3 of the
  [arithmetic operators plan](https://github.com/kablorp/blorp/blob/9829b166ba73f1d14540971abefdd143e0c52d19/blorp_2/ARITHMETIC_OPERATORS_PLAN.md). In
  3 it is a compound assignment (`+=`, `-=`), which that plan rejects. In 3 it
  is a tensor dimension type (`Int[#1000]`), which is outside the bootstrap
  subset. See [compile failures](#compile-failures).
- **All 8 ports in `benchmarks/blorp_2/` compile, run and give the legacy
  compiler's output.** The six with exact output contracts in
  `bench_run.py` were checked on every run. The two accumulator extras were
  checked mode by mode (36 of 36 comparisons identical).
- **Plain code generation is close to the legacy compiler's.** By retired
  instructions, Blorp 2 is 0.78× the legacy count on `numeric_loop`, 1.00× on
  `fib`, 1.06× on `binary_trees` and 1.14× on `compiler_ast`. It uses about
  half the peak RSS on `binary_trees` (5.4 MiB against 12.0 MiB).
- **The library and ownership gaps are large.** On `list_ops`, Blorp 2 retires
  58× the legacy instructions and makes 94.1 M allocations against 9,665,
  because its `filter`, `reverse` and `sort_by` are temporary immutable
  divide-and-conquer algorithms. On `helper_accumulators record_loop`, it
  does 775× the legacy work, net of startup: a known quadratic case listed
  in the ROADMAP's [O2 known limits](../../blorp_2/ROADMAP.md#o2-record-update-binds-before-it-rebuilds).
  The legacy compiler has the reverse problem on `record_result`: 14,646 M
  instructions and 6.1 GiB peak RSS at 65,536 steps, against Blorp 2's 53 M
  instructions and 5.9 MiB.

## Setup

- Host: Apple M4, 10 cores, 32 GiB, macOS 26.7.1, Apple clang 21.0.0
  (clang-2100.3.34.2). The machine was shared with other sessions; its
  1-minute load average was 3.4–6.4 during the runs.
- Source: `356bd1406` (main), plus this change's benchmark-tooling edits,
  which are not compiler inputs.
- `bin/blorp`: built by `make` at `356bd1406`, FRESH per
  `scripts/compiler-build-status`, `cli=-O0 runtime=-O2`, sha256 `520842623cdb…`.
- `blorp_2/build/compiler`: built by `make -C blorp_2 compiler` at the same
  revision, sha256 `3064266c5fe7…`.
- Both lanes compile their generated C with `bench.sh`'s flags:
  `-fwrapv -O2 -march=native -flto -pthread`. Timed binaries use
  `-DBLORP_MEMORY_DIAGNOSTICS=0`. Allocation binaries are built separately
  with `-DBLORP_MEMORY_DIAGNOSTICS=1` and run under `BLORP_LEAK_CHECK=1`
  (legacy) or `BLORP_LEAK_CHECK=strict` (Blorp 2).
- Inputs: the suite's own sources and `benchmarks/args/` (`binary_trees 15`,
  `control_flow_accumulators nested 65536`,
  `helper_accumulators list_helper 16384`). These are unchanged from
  `356bd1406`, whose git tree ids are `benchmarks/blorp` `08f9bbb5643`,
  `benchmarks/blorp_2` `eaf74e63c8d` and `benchmarks/args` `0d6d727b662`.

Raw logs, the probe's generated C, and the driver scripts are in the main
checkout's ignored `build/blorp2-runtime-bench-2026-10-31/`.

## Method

Each round runs every ported benchmark once, in this order: `numeric_loop`,
`fib`, `binary_trees`, `compiler_ast`, `list_ops`, `compiler_emit`,
`control_flow_accumulators`, `helper_accumulators`:

```bash
BENCH_WARMUPS=1 BENCH_RUNS=1 BENCH_RESOURCE_STATS=1 bash benchmarks/bench.sh <name>
```

There were five rounds, all run serially. Within a round, each benchmark runs
legacy, then Blorp 2, each with one untimed warmup. The lanes therefore
alternate across five timed samples each. Then came one allocation round:

```bash
BENCH_ALLOC_STATS=1 bash benchmarks/bench.sh <name>
```

- **Time** is the in-process `BENCH` marker: the median of the five samples,
  with the spread (max−min)/median.
- **Instructions** are the minimum, and **peak RSS** the maximum, across the
  five whole-process `/usr/bin/time -l` samples (`BENCH_RESOURCE_STATS=1`,
  added with this report).
- For context, a bare `true` retires about 12 M instructions on this host.
  The accumulator benchmarks' `none` modes retire 12.0 M (legacy) and
  11.6 M (Blorp 2). That startup cost dominates any row under about 50 M
  instructions.

List, String and set helpers are linear in both compilers. Record field
updates are not:

- `record_loop` stays quadratic in Blorp 2. The ROADMAP's O2 known limits
  attribute this to the loop header holding the old record, so a fix waits
  on loop-header last-read drops.
- `record_helper` and `record_inherited` still copy about 11× the legacy
  work.
- The legacy compiler is quadratic on `?=` `record_result`, as that ROADMAP
  section records. This run also shows a 6.1 GiB peak RSS for it at 65,536
  steps.

- **Infix operators (23 sources).** The `-` and `%` diagnostics match the
  rejections listed in the plan's [problem statement](https://github.com/kablorp/blorp/blob/9829b166ba73f1d14540971abefdd143e0c52d19/blorp_2/ARITHMETIC_OPERATORS_PLAN.md#problem-and-scope).
  The `*` (`dict_ops`) and `/` (`spectral_norm`) cases surface as generic
  parse errors at the operator. Milestone 3 adds all four operators.
- **Compound assignment (3 sources).** The plan
  [rejects](https://github.com/kablorp/blorp/blob/9829b166ba73f1d14540971abefdd143e0c52d19/blorp_2/ARITHMETIC_OPERATORS_PLAN.md#deviations-from-the-legacy-compiler)
  compound assignment with a teaching message, so these sources need
  rewriting even after milestone 3.
- **Tensor dimensions, concurrency and the missing library modules.** These
  (`dict`, `set`, `vector`, `instrumentation`, `units`, and the local
  `./support/benchmark` helper) are outside the
  [Blorp 2 scope](../../blorp_2/AGENTS.md#scope) today. Blorp 2's library has
  only `bool`, `float`, `int`, `io`, `list`, `option`, `path`, `process`,
  `result`, `string`, `system`, `test` and `traits`.

## Caveats

- **Wall time is noise here.** Other sessions were loading the machine.
  Instruction spreads stayed within about 1% except on startup-dominated
  rows.
- **Whole-process counters include startup**, about 12 M instructions per
  run; `compiler_emit`'s 0.81 ratio is mostly startup. Net of the `none`
  controls, the ratio is about 0.66, but `compiler_emit` has no `none` mode,
  so that figure is approximate.
- **`list_ops` and `compiler_emit` compare current libraries, not code
  generation.** `binary_trees` and `compiler_ast` use different recursive
  representations ([audit](../AUDIT.md), [README](../README.md#blorp-2)).
- **The legacy compiler was built at `-O0`**, the `make` default. That
  affects only the compiler itself, not the benchmark binaries: both lanes'
  generated C is compiled at `-O2`.
