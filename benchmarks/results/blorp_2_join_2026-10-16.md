# Blorp 2 M2.1: bound and statement matches as joins

Validated 2026-10-16 in worktree `blorp2-lists`, branch `blorp2/join`, on
main `23aa093ab`. Scope is the pilot compiler; the host compiler is
unchanged. Owned-input measurements are proxies: the pilot cannot compile
itself yet, so they cover the e2e fixture corpus, not a self-compile.

## Design

A match that is not a function's tail is a join. Checking publishes it as
`CheckedForm.Match(CheckedJoin)` whose arms carry a value each; the tail
match keeps `CheckedMatchBody`. A bound match's first arm decides its type
(a reassigned `var` decides it instead); a statement match is Void and its
arms may end with a statement. A known expected type decides every arm:
the first arm decides only for a new binding. At a Void function's tail the
match is Void and each arm's value is discarded after tail analysis, as a
plain Void tail value is. A self call at the tail of a nested match is
rejected (staged) in `@tail_recursive` functions. An arm may reassign only bindings it
declares, because a join carries one value to its continuation, not new
versions of outer variables. A match inside a larger expression is
rejected until it is bound.

Lowering makes the join one `JoinValue` definition, which is its own single
parameter. Its arms are `JoinArm { label, definitions, value }`: an arm
only yields, so a yield cannot end a function and a backedge cannot leave a
join. Every block's values stay one consecutive
interval: a block's joins' arms are numbered after the whole block, in join
and arm order, each arm followed by its own joins' arms. Ownership owners
follow the same order, so insertion, verification and emission each walk
one rule.

Ownership: a join reads, at its own position, every value its scrutinee
and arms read from outside the arms, so an enclosing owner whose last use
is inside an arm is dropped after the join by its block. A yield moves only
an owner made in its arm; a yielded enclosing value is acquired again.
Every edge into a join therefore leaves the same enclosing owners live. The
verifier checks yield type, an arm-made transferred owner and discharged
arm locals at each yield, and rejects any enclosing discharge inside a join
arm where it happens, so every edge leaves the enclosing owners live.
Enclosing blocks are shared views, not copies: a tail arm flags the prefix
owners it discharges, by owner number, copying the flags once on its first
discharge. Lowering publishes each join's outside reads with the join, inner
joins first, so insertion's use analysis never walks its arms; a repeated
read rewrites the same last-use slot, so the list is not deduplicated.
Lowering and insertion build a join's definition only once its arms exist;
until then the block holds it as an awaiting entry.

A join arm's early return is deferred to M2.3, which adds it with `?=` as
its producer: an arm exit union, the owners live at each join (with the
position each block drops them after), drops of the whole scope stack except
a transferred owner, the verifier's return rule for an arm and "some arm
continues", `return` in an emitted case, and fixtures with owners live in
two enclosing scopes. The first arm's type could also explain a `None` or
`[]` first arm that needs an expected type; that help is a later diagnostic
improvement.

Emission declares the join's local before its `switch` (the only non-const
value local), assigns it in each braced case and breaks; a managed join's
owner aliases the local after the switch. Precedent: SIL/MLIR block
arguments with nested arms instead of a CFG.

## Nesting and prefix-owner scale

Minimum retired instructions of three runs, same flags; probes from the
adversarial pass. `base` is the `23aa093ab` pilot, which rejects joins at
checking, so its nesting figures cover only lexing, parsing and part of
checking:

| Probe | base | first round (`c69530ee9`) | second (`596a08cc5`) | this round |
| --- | ---: | ---: | ---: | ---: |
| 16 nested bound matches | 62,662,644 | 99,795,216 | 98,659,987 | 98,591,543 |
| 64 nested | 106,148,391 | 328,241,583 | 293,155,030 | 295,422,772 |
| 256 nested | 490,224,737 | 3,365,290,280 | 2,149,960,557 | 2,203,315,908 |
| tail match, 800 prefix owners | 969,587,995 | 1,050,159,860 | 990,534,007 | 993,329,965 |

Publishing each join's outside reads once removed the per-level re-walk: at
256 levels, instructions fall 35% from the first round. Lowering's reads are
not deduplicated, so a deep chain repeats outer reads at every level: with
one outer read per level, +2.5% instructions and 287,091 against 255,224
allocations at 256 levels, compared with the second round's deduplicated
table, which this round deletes. The review measured the worst case, where
every level reads the same outer value 16 times (generator and timings in
the session scratchpad's `review_m21b/gen/`), second round against this one:

| Depth | Instructions | Allocations |
| --- | ---: | ---: |
| 32 | +4.8% | +8% |
| 128 | +12% | +35% |
| 256 | +15% | +70% (797k to 1.36M) |

Deduplication is not kept: a join's reads never include values defined
inside it, so duplicates are bounded by read occurrences times the levels
they cross, and removing them would need the per-function mark table this
round deleted. The remaining growth per level is mostly outside joins. The input itself grows with
depth squared (each line is indented), and lexing is most of a 256-level
profile. Emission copies each nested join's text once per enclosing level,
17% of that profile; a single output accumulator would remove it, and is
left for a later change. With per-owner discharge flags, the 800-owner
prefix costs +2.4% over base, down from +8.3%.
