# Blorp 2 structural tuples

The compiler accepts structural tuples with two to four ordered elements,
literal-index reads, recursive match patterns and flat declaration/for
destructuring. Check publishes structural types and logical projections;
Specialize interns an explicit `StructuralTuple` origin in the existing record
table. Concrete tuples use ordinary managed records and generated field
identities. No source declaration identities, tuple runtime, layout cache or
compiler-source tuple adoption are introduced.

Void remains in logical field ordinals and evaluates normally, but the shared
record emitter omits its physical storage. An all-Void tuple has only the
managed header. Own consumes existing selection acquisition plans; Verify
independently checks the actual parent borrow, field identity/type and nested
projection guards. These boundaries have positive, malformed-product and
deliberate-mutation coverage.

## Direct controls

Each control uses three normal samples and one strict compilation. They compile
the actual main fixture, including normal library loading; they are not isolated
tuple-operation timings. Tuple syntax is rejected by the baseline, so its cost
is not a meaningful before/after denominator. The nominal control uses an
ordinary three-field record and runs baseline/candidate pairs in alternating
order.

## Current-source self-compilation

This proof uses the changed current source and library, separately from the
frozen-input cost comparison above. The pinned seed's final build supplies A;
A emits the current compiler and the unchanged Makefile links B, B emits and
links C, then C emits again. Every stage links at `-O0` with memory diagnostics.
A, B and C emit identical 18,746,512-byte C, SHA256
`46c041be4c5be389cd5e6b6d288f5abd8e673ca78b003914849232ac456ee4e3`,
with empty normal streams.

Strict B self-compilation and strict ASan/UBSan B self-compilation reproduce
those exact bytes. Each balances 30,783,171 allocations/releases, with zero
tracked leaks or outstanding bytes and no sanitizer diagnostic. All linked and
executed C is unchanged. A and B agree exactly on all 568 maintained fixture
files: 478 accepted and 90 rejected, including status, stdout, stderr and
emitted-C presence/bytes. The explicit stage script and artifacts are retained
under `build/tuple-evidence/fixpoint/`.
The complete self-built B e2e then passed **572/572**; the explicit contracts
finished with exit 0. Closing guards found no source/library drift, and the
external observer remained FRESH with unchanged identity.

## Validation and limits

Independent hosted components passed **4,305/4,305**, with the mandatory
target-owned text factory **1/1** (30 balanced target allocations/releases).
Complete candidate-A e2e passed **572/572**, including all seven tuple cases.
Their real main functions run from unchanged strict C11 output with ASan/UBSan
and normal/strict target accounting. Tuple target allocation/release counts are
1 / 16 / 12 / 27 / 24 / 6 / 33. Rejections assert exact message, help and span.
The frozen baseline rejects the canonical triple at its comma, establishing
the red-before behavior.

The A e2e run retains **477 cost-only FAIL records** under the explicitly approved
`record-initial-bootstrap-debt` policy, with required counters: 116 first fail
on allocation limits and 361 on instruction limits. The separate B run records
its own **477 FAIL rows**, independently counted as 116 allocation-first and
361 instruction-first reasons. All seven tuple compilations
exceed the existing instruction ceiling; nested32 also has 163,833 compiler
allocations against 140,000. These are outstanding debt, not passing budgets.
The separate matched feature ceilings above pass without this exception.

Deliberate mutations fail the intended tests: parser collection order (2/17),
tuple field ordinal (2/27), ignored acquisition plan (1/2), and bypassed actual
parent-borrow verification (1/7). Source bytes were restored, then owning suites
passed. Independent code review reports zero blockers, should-fixes or nits.

Handwritten production changes are 1,200 added / 223 removed, **net +977**;
tests are 1,708 added / 19 removed, **net +1,689**. Necessary positive and malformed
ownership coverage exceeds the initial test-size estimate; no production ceiling
was changed and no coverage was deleted to lower the count.

Hosted checks used the separately verified FRESH observer in the main checkout,
SHA256 `16b0dc7ed23d8066ec3ff8ff5983850e0e7a02bf65579871e78f2f2cfeb87cb6`,
